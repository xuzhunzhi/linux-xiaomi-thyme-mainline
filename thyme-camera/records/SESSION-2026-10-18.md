## 已修的用户态问题

1. libcamera 0.7 默认 EGL GPU debayer 与桌面 Zink 配置产生分配失败并 abort。
   已安装 `libcamera-cpu.yaml` 至手机
   `/home/ubuntu/.config/libcamera/configuration.yaml`，强制 CPU。
2. CPU 路径 PipeWire 首帧出现 std::array 越界 abort。
   GDB 在 `DebayerCpu::updateGammaTable()` 看到 DebayerParams 黑电平、gamma、
   gains 为巨大垃圾数，blackIndex=0xffffffff。
   根因：SoftwareIsp 的缓存 debayerParams_ 未初始化，而 computeParams() 为异步。
   修复：同步 IPA init() 成功后调用 saveIspParams()，读取已写入共享区的默认值。
3. 采集启动失败时 SimplePipelineHandler 调用 SoftwareIsp::stop()，
   而 ISP 线程尚未 start；阻塞调用 Debayer::stop 永久等待不存在的工作线程。
   修复：stop() 开头检查 ispWorkerThread_.isRunning()，未启动则返回。
   修复后同类 CCI 启动失败会令摄像头 node 报错，但 PipeWire 仍可响应并正常重启。

证据与代码：

- `libcamera-cpu-crash-backtrace.log`：原始崩溃堆栈及垃圾参数。
- `libcamera-0.7-softisp-fixes.patch`：上述两处软件 ISP 修复。
- `libcamera-0.7.0-thyme-source.tar.gz`：含最终补丁的完整源码（不含 .git）。
- 上游基准 libcamera v0.7.0，commit b7854fd07d42168f099b5ce30d1702e0e0875bf5。

## 已部署的独立 libcamera

手机源码 `/tmp/thyme-libcamera-v070`，构建 `/tmp/thyme-libcamera-build`。
安装 `/opt/thyme-camera`，没有覆盖发行版库。
桌面用户 drop-in：
`/home/ubuntu/.config/systemd/user/pipewire.service.d/90-thyme-camera.conf`：

```ini
[Service]
Environment="LD_LIBRARY_PATH=/opt/thyme-camera/lib"
```

已核对 /proc/PID/maps，PipeWire 确实加载 /opt 下的 libcamera、base 和 simple IPA。
ldd -r 检查现有发行版 libspa-libcamera 插件与新库无未解析符号。
本地 drop-in 副本为 `90-thyme-camera.conf`。
独立库仅 simple pipeline、simple IPA、CPU ISP；EGL 开发库未装，GPU 未编译。

构建命令：

```sh
meson setup /tmp/thyme-libcamera-build /tmp/thyme-libcamera-v070 \
  --prefix=/opt/thyme-camera --libdir=lib --buildtype=debugoptimized \
  -Dpipelines=simple -Dipas=simple -Dcam=disabled -Dqcam=disabled \
  -Dgstreamer=disabled -Dpycamera=disabled -Ddocumentation=disabled \
  -Dlc-compliance=disabled -Dv4l2=disabled -Dtest=false \
  -Dtracing=disabled -Dlibunwind=disabled
ninja -C /tmp/thyme-libcamera-build -j4
sudo -n meson install -C /tmp/thyme-libcamera-build --no-rebuild
```

手机本轮另装 libyaml-dev、python3-ply。此前已装 v4l-utils、libcamera-tools、gdb 等。
若重装库，先正常停止 PipeWire，避免在运行时覆盖正在映射的文件。
若服务已死锁，可先发起 stop --no-block，再 kill 该用户 pipewire；注意等待
wireplumber 停止完成。一次恢复因旧 WP 停止等待约 90 秒，随后恢复正常。
